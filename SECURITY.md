# Security Policy

## 🔐 Responsible Disclosure

We take the security of Phantom Recon seriously. If you discover a vulnerability in this project, please follow responsible disclosure practices.

## 📋 Supported Versions

| Version | Supported          |
|---------|--------------------|
| 1.0.x   | ✅ Yes             |
| < 1.0   | ❌ No              |

## 🐛 Reporting a Vulnerability

**DO NOT** create a public GitHub issue for security vulnerabilities.

Instead, please:

1. **Email**: Send details to `security@phantomrecon.example.com`
2. **Subject**: `[SECURITY] Brief description of the vulnerability`
3. **Include**:
   - Description of the vulnerability
   - Steps to reproduce
   - Potential impact
   - Suggested fix (if any)

### Response Timeline

- **Acknowledgment**: Within 48 hours
- **Initial Assessment**: Within 7 days
- **Fix & Release**: Within 30 days (critical issues faster)

## ⚠️ Ethical Use Disclaimer

**Phantom Recon** is designed exclusively for **legal and authorized** security testing purposes.

### Acceptable Use

- ✅ Testing systems you own
- ✅ Testing with explicit written authorization
- ✅ Educational and research purposes on isolated environments
- ✅ Bug bounty programs where allowed
- ✅ Compliance and audit testing

### Unacceptable Use

- ❌ Unauthorized access to any computer system
- ❌ Testing without explicit written permission
- ❌ Denial of service attacks against production systems
- ❌ Data exfiltration from unauthorized targets
- ❌ Any activity that violates applicable laws

## ⚖️ Legal Notice

Usage of Phantom Recon for attacking targets without prior mutual consent is **illegal**. It is the end user's responsibility to obey all applicable local, state, and federal laws.

The developers assume **no liability** and are **not responsible** for any misuse or damage caused by this program. Use responsibly.

## 🔒 Security Best Practices

When using Phantom Recon:

1. **Always get written authorization** before testing
2. **Scope your tests** — only test what's explicitly approved
3. **Use a VPN** and isolated testing environments
4. **Keep reports secure** — they contain sensitive information
5. **Follow responsible disclosure** if you find vulnerabilities
6. **Comply with all applicable laws** in your jurisdiction
